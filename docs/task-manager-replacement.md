# 任务管理器替代目标与验收范围

用户新增目标（2026-09-16）：继续优化所有东西，特别是前端动效；最终让应用能够完全替代日常使用的任务管理器。

本目标扩展原始 Master Build Prompt 的生态可视化定位，不取消 Garden / Eldritch、主题扩展、中英文字体、真实图标、壁纸、生成素材和连续动效要求。不能用“生态演示已通过”证明此目标完成。也不把系统安全界面、受保护进程或权限边界解释为需要绕过的限制。

## 目标建立时的源码证据（后续进展见文末）

- 原生采集：`src-tauri/src/collector.rs` 采集全表后执行 `truncate(500)`；返回的总进程数可能大于可查看记录数。当前不能宣称完整进程覆盖。
- 生态视图：`src/ecology/population.ts` 根据资源评分选择有限节点；生态密度不是完整进程清单。
- 数据模型：`src/types/system.ts` 包含 CPU、内存、启动时间、父 PID、可选线程数和路径；缺少完整的磁盘/GPU/用户/服务/启动项数据模型。可选连接字段不等于真实连接采集已经实现。
- 原生命令：`src-tauri/src/lib.rs` 目前注册采样、平台名、图标提取；没有结束进程、优先级、启动项或服务管理命令。
- 详情历史曾按 PID 串联并将缺样补零；本轮修正为同一 PID＋启动时间的连续观测尾段，防止误把不同进程或未知样本画成同一资源曲线。
- 高密度 120 Hz、原生打包后的持续性能、参考图完整复刻和真正 Agent 任务遥测仍未完成验收。

## 分阶段实现与完成证据

1. **可信观测与完整清单（优先）**：单独提供完整的进程表，按名称/PID/CPU/内存排序，按名称/PID/路径过滤，稳定选择和键盘访问，处理数千行而不重建整表。生态视图继续作为另一种观察方式。移除静默截断，或提供明确分页/覆盖标记。证明：与同一权限下的 Windows 进程枚举对照，无可访问条目静默遗漏；长列表实际浏览器/原生测试。
2. **指标口径与详情**：明确总 CPU 与进程 CPU 的核数归一口径、内存类型和单位；未知、拒绝访问、过期、演示不能伪装成实测零。补齐进程树、命令行、用户、文件路径与签名信息。证明：可控 CPU/内存/多线程负载对照，以及 PID 复用和缺样测试。
3. **安全的进程操作**：结束进程/进程树、打开文件位置、复制详情及适当的优先级操作。每次操作以 PID＋启动时间重新核对目标；破坏性操作明确确认，受保护目标和权限失败清晰反馈，禁止自动提权或自动结束进程。证明：只对专用测试子进程进行原生验收，PID 复用时拒绝误操作，父子退出可追踪。
4. **系统性能页**：CPU 核心、内存、磁盘、网络、GPU 的实时与历史视图；可用性与来源明确，采样不阻塞 UI。证明：逐指标对照可信系统计数器，断开设备、权限不足、休眠恢复、长时间运行检查。
5. **任务管理器其他工作流**：应用分组、详细信息、启动应用管理、服务和用户会话视图，明确哪些操作需要管理员权限；评估应用历史/效率模式等平台支持，支持前不显示可用假按钮。证明：逐项能力矩阵、授权测试环境和可恢复操作测试。
6. **日常替代交付**：托盘、快捷键、启动/恢复、崩溃恢复、可访问性、本地隐私、签名/安装/更新、低自身开销。保留原生任务管理器作为系统故障恢复渠道，不擅自改写系统快捷键或注册表。证明：真实 Windows 安装包和持续运行验收、内存/CPU/GPU 开销记录、完整回归清单。

以上是验收范围，不是已实现功能列表。各阶段可以并行推进，但不能以低层级单元测试替代原生操作或视觉验收。不同权限能见度差异必须记录，不能声称比系统权限允许范围更完整。

## 协同与下一项交接

前端动效维护在 `perf/scene-asset-preparation` / PR #7；不覆盖集成工作树的主题素材修改，也不复用其原生输出目录。扩大范围后的采集协议、完整进程表和原生操作需在 GitHub 明确交接，避免只修改前端标题却仍消费被截断的进程数据。

下一项优先交付：完整进程表的数据覆盖方案和可操作的排序/筛选/选择流程。结束进程功能必须在身份校验、确认 UI、权限反馈同时完成后才对用户开放；本轮没有执行任何真实进程终止。

### 前端进程清单首版进展

现已提供独立清单入口，可对收到的记录按名称/PID/路径筛选，按 CPU/内存/线程等排序，每页 50 条，点击后定位详情；匹配条数、收到条数和快照报告总数分别显示。查询逻辑通过 5000 条合成记录测试，无额外前端截断。浏览器验证覆盖中文 Garden 和英文 Eldritch。此进展不意味着原生 500 条上限已解决，也不证明完整系统枚举或数千真实进程下的性能。下一步仍须完成原生覆盖和指标口径对照，再加入安全操作。

### 原生进程覆盖后续进展

采集器已移除 `truncate(500)`。独立 Windows Rust 测试实际枚举并返回 566 个进程，返回 PID 集合与采集器持有的枚举集合逐项一致；前端组件另通过 1500 条记录的最后一项检索/定位回归。证据见 `design/qa-native-process-coverage-2026-09-16.md`。此结论限于保留采集器能枚举的记录，不是绕过权限、捕获采样间全部短命进程或已完成任务管理器全能力替代。安装包和集成窗口尚需重建验收，CPU 口径及完整历史的内存成本仍需验证。

### 当前快照关系导航与历史减负

检查器已加入父进程定位，按当前父 PID 和启动时间作有限推断；缺失、未知时间或父进程启动晚于子进程时不开放跳转。点击再次检查当前选择与双方生命周期，导航后保留检查器焦点。中文 Garden 浏览器验证了 python → code 的路径。这不是完整历史进程树，也不是结束进程树的身份授权依据；英文/克苏鲁、长名称与原生关系仍待验收。

历史改为轻量数值观测，当前快照仍保留全表与元数据。1500 进程、120 样本的合成测试序列化体积由 54,608,821 降至 15,815,221 字节；该数值不能代替实际堆内存与长期运行测量。另已完成进程 CPU 核数归一、线程计数来源优化及未知值区分，证据见 design 下对应测量记录。完整系统性能页、用户/服务/启动项、原生安全操作整合与安装版持续验收仍未完成。
