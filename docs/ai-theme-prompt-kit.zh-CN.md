# Process Garden · AI 主题素材提示词包

把下面的「总提示词」复制到其他 AI，改掉主题需求即可开始。支持绘图的 AI 可以逐张出图；纯文本 AI 可以产出逐张绘图提示词，再交给绘图工具。建议在同一会话生成整套图片，并反复提供第一张确认过的图片作为风格参考。

**应用入口：** 主题菜单 → 添加主题 → AI 素材与自定义图片。填写想法并复制提示词，将 AI 生成的图片逐张上传到对应素材槽，预览后保存。支持只替换部分图片，也支持导出带图片的 v2 `.pgtheme`，导入时会先显示确认预览。图片只保存在本机。动态旋转、漂移、出生和消失由程序驱动，静态图片不等于新的动画实现。

## 1. 总提示词（完整复制）

```text
你是 Process Garden 的主题美术设计师及游戏素材制作助手。请为我制作一套视觉统一、可拆分使用的桌面数字生态素材。

我的需求：
- 主题名称与世界观：雨夜里的玻璃温室
- 主要元素：苔藓、玻璃、雨滴、微光种子
- 主色 / 辅色：青绿 / 琥珀
- 气质：安静、精致、有生命力
- 避免元素：恐怖、血腥、文字、品牌标志
- 继承程序行为：garden（可改为 eldritch 或 cyberpunk）

产品背景：
Process Garden 把电脑进程显示成生态生物，内存影响大小、CPU 影响运动、父子进程通过连线关联。中心有一个生态核心，周围是进程生物，还有环境装饰、微型飞行生物、AI Agent 核心和任务胚胎。素材必须衬托真实数据，不能把界面、图标、进程名称、连线或数据烘焙进图片。

工作方式：
1. 根据需求确定一份简短美术规范：色板、材质、光源、视角、轮廓语言，以及八类生物分别用什么形象表达。需求不完整时给出明确默认值，不要反复追问。
2. 列出下方全部文件，分别写出可独立复制使用的完整英文绘图提示词。每条必须重述本主题的风格与技术要求，不能只写“同上”。
3. 如果你支持绘图，先生成核心图作为风格基准，再按清单逐张生成。每次输出说明文件名和完成进度。达到工具数量限制时准确标记待完成项，不要声称已交付整套。
4. 不支持绘图时，明确交付的是提示词，不能用图片链接或文件名冒充实际素材。
5. 所有文件完成后给出逐项验收表。确实支持文件输出时，提供真实图片及素材 ZIP；不支持时说明需要用户保存及命名。不要制造下载链接。

共同要求：
- 原创设计；统一视角、材质精度、光线与色板。轮廓清晰，在约 48 像素的小图预览下仍能分辨不同物种。
- 输出 PNG 静态素材。下面的分辨率是建议交付尺寸，不是声称工具一定支持的尺寸。达不到时报告真实尺寸，保留正确比例。
- 除背景与天体图集外，使用均匀纯黑 #000000 底，无地面、投影、场景、灰雾、边框、文字、编号、水印或棋盘格。主体暗部也应有足够亮度，避免程序去黑时损失形体。
- 所有 atlas 都是严格 2×2 等分正方形图集，建议 2048×2048。四格阅读顺序固定为左上、右上、左下、右下。不要绘制分割线。
- 每格只有一个独立主体，居中，每格四周至少保留约 12% 空白；触须、翅膀和光晕不能跨格或碰边。四格大小感相近，不能把四个物件聚在整张图中央。
- 不生成应用图标、字体文件、截图、UI 面板、统计数字或整页海报。

必须交付的素材：
A. background.png：建议 2560×1440，16:9。暗色生态环境，细节集中于边缘和底部；中央约 60% 范围低对比、低细节，给数据和生物留空间。无中心主角，不画核心。
B. core.png：建议 1536×1536。一个居中的主生态核心，正面或轻微俯视，近圆形整体轮廓。关键细节集中在画面中心，外缘逐渐归于纯黑，避免边缘裁切。亮度克制。
C. process-atlas-v1.png：左上=观察者；右上=神经网络生物；左下=幼体；右下=构造体。四种不同轮廓，属于同一世界。
D. process-atlas-v2.png：左上=孢子群；右上=盘绕根系或触须；左下=信号光丝；右下=壳状生物。注意右下是普通物种图，不代替独立 Agent 核心。
E. process-atlas-v3.png：与 v1 相同角色顺序，每种角色的第二个物种变体，保持家族特征而非简单换色。
F. process-atlas-v4.png：与 v2 相同角色顺序，每种角色的第二个物种变体。
G. habitat-atlas.png：四种低矮环境装饰，分别为栖息基座、植物或对应结构簇、小型液体或能量池、石块或矿物簇。无完整场景，不喧宾夺主。
H. pollinator-atlas.png：四种轮廓不同的微型飞行生物或同世界观微型装置，例如蝶形、蜻蜓形、甲虫形、蛾形。保持独立完整，适合程序移动和旋转。
I. agent-growth-atlas.png：左上=独立 AI Agent 神经核心；右上=早期任务胚胎；左下=中期任务胚胎；右下=临近孵化任务胚胎。后三格表现同一物种连续成长，体轴和视角一致；不是四个不相关角色，也不是四帧走路动画。
J. celestial-atlas.png：左上=日间天体；右上=夜间天体；左下=异化日间天体；右下=异化夜间天体。各自独立居中，无天空背景。自定义上传支持纯黑底或真正透明的 alpha 背景，不要画棋盘格假装透明。
K. capture-atlas.png：左上=水平直杆；右上=朝右抓取末端；左下=根部接口；右下=空心缠绕环。选择藤蔓 vine、触手 tentacle 、机械缆索 cable 或接引光束 beam（赛博默认；四格改为水平光柱、接触辉光、投射口、空心锁定光环，程序驱动直线吸回），材质、光向与主题一致。生成精致立体部件，不画完整捕获场景；程序负责伸出、缠住、拖入反馈和回收动作。
L. core-maw.png：仅当继承 eldritch 时必需。与 core 同一实体、同一视角的张口吞噬状态，纯黑底，口腔中心对齐画面中心，主要轮廓和尺寸与 core 匹配。无文字、碎片生物或血腥。其他基底可省略并标明不适用。

v1–v4 共包含 16 个普通生物，另有四格 Agent 成长图。标准套装共 11 张 PNG，eldritch 套装共 12 张。不要把清单合并成一张大海报。

导入限制：每张 PNG 最多 8 MiB，整套最多 64 MiB，边长 64–4096 像素，单图像素数不超过 9,437,184。背景宽高比 1.3–2.4，其余必须为偶数边长正方形。用户将逐张上传素材槽，由应用生成可导出的主题包，无需 AI 编写带图片的 manifest。

最后另附素材清单，记录每个文件的用途、真实尺寸、背景类型、格子顺序、是否已经生成、需要的后处理。记录所用模型及参考图来源（不知道就标记未知），不要虚构商用授权结论。
```

## 2. 单张返修提示词

把出问题的图片附给 AI，并填写文件名和问题：

```text
请只修复附件这一张 Process Garden 素材。
文件名：[填写文件名]
发现的问题：[例如：右上触须跨格、黑底变成灰色、四格顺序错误]
保持已经确认的色板、材质、视角、角色身份和其他正确内容。按照原文件的尺寸比例及格子顺序重新输出。
如果是图集，必须严格 2×2 等分，每格主体居中，四周留白，所有肢体和光晕不跨格，不添加文字和分割线。
请提供修复后的实际图片；无法执行的修复请明确说明。
```

## 3. 可导入主题参数提示词

这一步可以单独使用，也可以在同一会话完成。生成的参数会继承内置图片，不会自动使用上面生成的图片。

```text
请根据已经确定的 Process Garden 美术方向输出一个完整、严格合法的 manifest.json。若本会话尚未确定美术方向，默认使用“雨夜玻璃温室、青绿与琥珀、安静精致”的主题，basedOn 设为 garden。
只输出 JSON，不使用注释，不省略字段，不增加字段。

字段要求：
- schemaVersion: 1
- id: 2–49 位 ASCII 字母、数字、下划线或连字符，以字母或数字开头；不得为 garden、eldritch 或 cyberpunk。
- name: 含 en-US 和 zh-CN 两个非空名称，每个不超过 64 字符。
- version: "1.0.0"
- author: "Local user"
- basedOn: "garden"、"eldritch" 或 "cyberpunk" 之一。
- colors: 必须完整包含 background, backgroundElevated, panel, panelStrong, border, borderStrong, text, textMuted, primary, secondary, tertiary, warning, danger, success。所有值使用六位十六进制颜色。背景深暗，正文和次级文字在面板上清晰可读，警告和危险色有明确区分。
- typography: 固定为 {"display":"Space Grotesk Variable","body":"Inter Variable","editorial":"Inter Variable","mono":"JetBrains Mono Variable","cjkDisplay":"Noto Sans SC","cjkBody":"Noto Sans SC"}。
- effects: 完整包含 glow, particles, vignette, grain，各为 0–1 的数字。
- motion: 完整包含 drift, pulse, tendril，各为 0–2 的数字。

禁止添加 assets、图片路径、远程链接、脚本、CSS 或字体下载地址。输出前自检字段、取值、JSON 语法及名称长度。
```

把真实 JSON 保存为 UTF-8 `manifest.json`，只将这一个文件放在 ZIP 根目录，将后缀改为 `.pgtheme`，再从应用导入。不要把外层文件夹一起压进去。应用的校验结果为准，AI 自检不代表已经通过实际导入。

## 4. 内置素材路径参考（用户无需操作）

以下以当前 `src/animation/sceneAssets.ts` 为准，素材清单采用方便用户理解的中性文件名，接入时需要映射到实际文件名：

| 提示词输出 | 当前程序路径，相对于 `public/assets/generated/` |
|---|---|
| background.png | `{family}/backgrounds/{family}-canvas-bg-v{N}.png`，garden 的 N=2，其余 N=1 |
| core.png | `{family}/cores/{family}-core-main-v{N}.png`，garden 的 N=2，其余 N=1 |
| process-atlas-v1…v4.png | `{family}/creatures/{family}-process-atlas-v1…v4.png` |
| habitat-atlas.png | `{family}/habitats/{family}-habitat-atlas-v1.png` |
| pollinator-atlas.png | `{family}/pollinators/{family}-pollinator-atlas-v1.png` |
| agent-growth-atlas.png | `{family}/agents/{family}-agent-growth-atlas-v1.png` |
| celestial-atlas.png | garden/eldritch 使用 `shared/celestial-atlas-v1.png`；cyberpunk 使用 `cyberpunk/celestial-atlas-v1.png` |
| core-maw.png | `eldritch/cores/eldritch-core-maw-v3.png` |

内置 garden 使用四张进程图集；内置 eldritch/cyberpunk 使用 v1、v2。自定义主题的三个基底均可上传并使用 v3、v4。天体图的前两格供非 eldritch 使用，后两格供 eldritch 使用；自定义天体只影响当前主题。

新增用户主题直接使用应用内上传入口，无需覆盖内置文件。图片会校验后保存在本机 IndexedDB，并以内容哈希记录在 v2 主题中；导出时自动打包。请自行保留来源和许可记录，应用的格式校验不代表图片获得商用授权。

验收时检查实际像素尺寸、四格顺序、纯黑或真实 alpha、边缘裁切、去黑后的细节、缩小后的物种辨识度，以及背景叠加数据后的可读性。生成工具的文件重命名、精确构图与透明输出能力各不相同，必要时需要后处理。
